Managed MCP

How a side project to make REST APIs consumable by AI agents grew into a startup's v1 product — and led to an open source contribution merged into FastMCP.

Role

The Problem

AI agents built on Claude and GPT are only as useful as the tools they can access. But connecting an agent to an existing REST API requires manually writing tool definitions for every endpoint — a tedious, error-prone process that breaks every time the API changes.

For teams that want to give their AI agents access to internal APIs or third-party services, this creates a real bottleneck. The answer shouldn't require a developer to hand-write wrappers.

What I Built

A platform that takes an OpenAPI spec — either pasted directly or fetched from a URL — and automatically generates and hosts a live MCP server from it. Any REST API with an OpenAPI spec becomes instantly consumable by AI agents, with no manual tool definition required.

The core insight: OpenAPI specs already describe every endpoint, parameter, and response schema. That's everything you need to generate MCP tools. The platform just needed to connect the two.

Built end-to-end: authentication, server persistence in DynamoDB, live mounting so servers are available immediately after creation, and a frontend for managing servers and browsing a curated marketplace of pre-built integrations.

Key Decisions

Dynamic generation over static wrappers. The alternative was providing templates or a CLI to scaffold MCP servers. Dynamic generation is harder to build but means zero maintenance burden for the user — the server always reflects the current API spec.

OpenAPI as the interface. Most APIs already have OpenAPI specs, so adoption friction is low. Users don't learn a new format — they paste something they already have.

Marketplace from day one. Rather than requiring every user to bring their own spec, the platform included a curated set of pre-built servers (Gusto, Outreach) so users could get value immediately without any setup.

Where It Led

The platform became Zalor's v1 product, shipped with Weav as the first design partner. Through that process — and 45+ customer discovery conversations — we identified a stronger opportunity in AI reliability testing and pivoted to behavioral simulation-based evals.

While building Managed MCP, I discovered a bug in FastMCP (the underlying library) where OpenAPI server variable templates like {region}.api.example.com were passed raw to httpx as the base URL, breaking all requests for any spec that used URL templating. I fixed it in the platform, then contributed the fix upstream.

The PR was merged into FastMCP main.

What I'd Build Next

The marketplace is the highest-leverage surface. Right now it's curated manually — the next step is letting the community submit servers, with a review and rating system. The harder product question is how to handle API authentication at scale: each user's credentials need to be isolated and securely injected into server requests.

The other gap is observability. Users have no visibility into which tools their agents are actually calling, how often, or whether requests are failing. Usage analytics per server would unlock a feedback loop that manual testing can't.
